# Phase 6A Kaggle GPU training smoke — source and run instructions

This notebook checks the Phase 6A gates in `SPRINT_PLAN.md`: correct supervised IPA targets and padding, FP16 AMP loss/gradients, a real optimizer update, and an actual checkpoint resume. It performs two updates on eight **training-only** examples. It does not evaluate validation/test, report CER, select a checkpoint, or begin the Phase 6B pilot.

## Inputs and Kaggle setup

1. Use the private local archive `outputs/phase6a_training_smoke_bundle_v1.zip` (2.43 MB). It has 12 frozen-train clips with raw and approved normalized references. The source WAVs were copied from the existing Phase 4 smoke bundle, their hashes were checked, and membership/text was matched to the private frozen train manifest. The source archive is private; it is excluded from GitHub.
2. Upload it as a **private Kaggle dataset** and attach it to the notebook with **Add Input**. Kaggle must expose the extracted folder containing `bundle_record.json`, `train_smoke_manifest.csv`, `SHA256SUMS.txt`, and `audio/`. If Kaggle shows only the ZIP, extract it into the private dataset before running. The notebook finds the extracted folder by marker; no user/slug or fixed mount path is required.
3. In Kaggle Notebook Settings, select **GPU Tesla T4** and enable **Internet** for the pinned public model/processor download. Keep the notebook and its outputs private because its live output contains training references and the checkpoint contains model weights.
4. Open [Phase-6A-Kaggle-Training-Smoke.ipynb](../notebooks/Phase-6A-Kaggle-Training-Smoke.ipynb) in Kaggle and run the first code cell. It pins **Transformers 4.57.1, Tokenizers 0.22.2, Hugging Face Hub 0.36.2, Safetensors 0.8.0** with `--no-deps`, leaving Kaggle's PyTorch/CUDA unchanged. If it installs packages, **restart the Kaggle session once** and run the notebook from the top. It requires the previously measured Kaggle PyTorch `2.11.0` build and an allocated T4. If Kaggle has changed either, stop and record the new environment rather than silently changing the experiment.
5. Run all remaining cells in order. The notebook checks the private bundle hashes, raw/normalized text, audio format, processor features, tokenizer round trips, target lengths, independent padding and EOS masking. It uses FP32 model weights and FP16 autocast/GradScaler for training.
6. The default is **micro-batch 2, accumulation 4**, one optimizer update from eight distinct training components, including a short and a near-30-second example. If a measured T4 allocation cannot fit, restart cleanly and change only `MICRO_BATCH=1; ACCUMULATION=8`, then record that deviation. Do not promise fit until the run measures it.
7. The checkpoint is written to `/kaggle/working/phase6a_private/`. The notebook reloads model, optimizer, scheduler, scaler and Python/NumPy/PyTorch/CUDA RNG states, then performs a second update. The final cell writes `phase6a_report_private.json` only if all gates pass. Download the executed notebook, report and checkpoint into private project storage. Do not add them to GitHub.

## Fixed policy for this smoke

- Model: `neurlang/ipa-whisper-base` at revision `949f7c4e4ee374b5202bc5886f6e4552e5ae2371`; seed 0; SDPA; no gradient checkpointing for the initial profile.
- Text: NFD, outer trim, collapse repeated ordinary spaces. Retain IPA marks and raw references.
- Training label: normalized IPA text tokens **without tokenizer-added special tokens**, followed by one EOS. The model inserts its decoder-start token while shifting labels. No English, Nyishi, transcribe, or timestamp token is forced into labels. This explicit supervised policy is recorded because B0 automatically selected English during generation; it is **not** a change to B0 evaluation.
- Collator: full `[80,3000]` processor features stacked; target sequences padded independently; only padding positions from the tokenizer attention mask become `-100`. The real EOS token remains a target.
- Optimizer: AdamW, `1e-5`, weight decay 0.01; gradient clipping 1.0. The two-update smoke uses a constant scheduler to verify both updates and resumed scheduler state. The sprint plan's linear decay/5% warmup is provisional for the later Phase 6B pilot, not a measured 6A requirement.
- For FP16 AMP, the notebook starts at loss scale 256 and retries the same eight examples at a lower scale when any unscaled gradient or the global norm is nonfinite. It records each attempt and stops after eight unsuccessful attempts; it never applies an optimizer update with nonfinite gradients. A nonfinite forward loss stops immediately. The notebook also fails closed on a wrong bundle, non-T4/mismatched stack, label loss, unchanged weight, or missing resume state. These are run-time gates; passing local syntax checks alone cannot establish that Kaggle training succeeded.
